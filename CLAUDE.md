# Working in this repo

## Issues

- GitHub issues are the backlog of record. Do not add a backlog file to the repo.
- When a change resolves an issue, close it with a comment that says what was
  done (commit, workflow or setting) and which release it is available in
  ("Available in: vX.Y.Z"; for dev-only work, the dev-<sha> build). Look the
  version up with `gh release list` rather than guessing.
- A partial fix gets the same note for the solved part and stays open with the
  remaining items listed.
- File follow-ups and out-of-scope findings as issues, one per item.
